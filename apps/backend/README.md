# CloudStart Backend

Python/FastAPI backend for the CloudStart MVP.

The current application already exposes the health contract used by the ALB and frontend. This first backend increment adds a maintainable persistence layer and a small CRUD slice without inventing a business domain that is not defined elsewhere in the repository.

## Stack

Python 3.12, FastAPI, Uvicorn, SQLAlchemy 2.x, psycopg 3, PostgreSQL and Alembic.

## Application structure

app/api/routes    HTTP interface
app/core          configuration
app/db            engine, sessions and declarative base
app/models        SQLAlchemy models
app/schemas       Pydantic API contracts
app/repositories  persistence access
app/services      application logic

## Existing endpoints

GET /health
GET /api/health
GET /api/info
GET /api/health/db

## CRUD slice

The first technical resource is Item.

POST   /api/items
GET    /api/items
GET    /api/items/{id}
PATCH  /api/items/{id}
DELETE /api/items/{id}

Listing accepts offset, limit and status filters.

## Database

The application does not create tables during startup. Schema changes are managed explicitly with Alembic.

alembic upgrade head
alembic downgrade -1

Before applying an autogenerated migration, review the generated migration file and SQL impact.

## Local development

From apps/backend:

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

Set DATABASE_URL or the DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD variables, then:

alembic upgrade head
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

OpenAPI:
http://localhost:8000/docs

The Item CRUD is intentionally a technical first slice. The repository currently does not define a finalized business entity, so this resource should not be treated as a claim about the final CloudStart domain model.
